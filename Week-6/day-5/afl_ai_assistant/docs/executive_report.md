# Executive Report: AFL AI Assistant
### Capstone Deliverable — Week 6 Day 5

---

## 1. Product Goal

The AFL AI Assistant is an enterprise-grade, domain-locked conversational AI system
purpose-built for the Australian Football League. It answers factual questions,
retrieves live statistics, and generates ML-backed match/player predictions —
all while enforcing strict guardrails to prevent off-topic queries and prompt injection attacks.

The system is designed to be deployable on a client property (e.g., Web3Geeks) as a
reliable, explainable, and secure AI product — not a general-purpose chatbot.

## 2. Architecture

```
User (Browser/API Client)
        │
        ▼
[Streamlit UI] ──HTTP──▶ [FastAPI /api/v1/chat]
                                  │
                          [LangGraph Pipeline]
                          ┌───────────────────┐
                          │   Router Node      │  ◀── Rule-based + LLM
                          │  (intent classify) │       classifier
                          └─────────┬─────────┘
                    ┌───────────────┼──────────────────┐
                    ▼               ▼                  ▼
              [off_topic/      [Tool Executor]   [blocked]
               blocked] ──▶    Node (5s timeout)
                               │        │
                    ┌──────────┘        └──────────┐
                    ▼                              ▼
          [Structured Retrieval]         [Match / Player Predictor]
           CSV → pandas lookup           Mock ML (→ real XGBoost)
                    │                              │
                    └──────────┬───────────────────┘
                               ▼
                        [Generator Node]
                       LLM synthesis + disclaimer
                               │
                               ▼
                    [Structured JSON Response]
                 {response, intent, latency, token_usage}
```

**Key Components:**
- **LangGraph** orchestrates the state machine; memory checkpointer maintains session context
- **FastAPI** exposes a typed, validated REST API with full OpenAPI docs at `/docs`
- **Streamlit** provides a zero-install chat UI with Debug Info panels
- **Abuse Handler** maintains per-session counters (off-topic ≥3 → block; injection ≥2 → block)
- **Structured Logging** captures every interaction with intent, latency, token usage, and abuse events

All ML predictions carry a mandatory disclaimer:
> *"This prediction is generated by a machine learning model and represents a
> probability, not a certainty."*

**Benchmark:** Our mock predictor was compared against a ladder-rank naive baseline
on 2023 AFL finals. The naive model achieves ~67% accuracy. A production XGBoost
model trained on form, injuries, and home-ground data would target **>65%** to be
meaningfully better than this baseline.

## 4. Known Limitations

| Limitation | Impact | Mitigation |
|---|---|---|
| **Data recency** | CSV contains 2023 data only; stats go stale after each round | Weekly ETL refresh (see monitoring plan) |
| **Mock ML model** | Prediction uses team name length as proxy — not real statistics | Replace with XGBoost trained on historical match data |
| **LLM dependency** | Router falls back to rule-based if API key unavailable | Rule-based fallback covers all test cases; LLM improves edge cases |
| **Guardrail edge cases** | Ambiguous queries near the AFL/off-topic boundary may misclassify | Monthly guardrail review + false-positive analysis |
| **No user auth** | Any caller can access the API | Add OAuth2/JWT in FastAPI for production |
